# ADR 0005: Recruiter hardening and hiring-manager collaboration

Status: implemented and verified locally. Collaboration migration `20261026180009` applied to staging Recruta on 2026-10-26. Application deployment follows the main-branch Vercel pipeline. Screening-v2 enqueue migration remains pending until the compatible worker is deployed.

Hiring-manager collaboration extends the recruiter job-to-applicant workflow. It does not require an employer portal account before creating an organization or job. Agency managers and assigned recruiters invite hiring managers/reviewers to a specific job or grant access to an existing active employer member. An organization role alone does not grant job access.

Recruiters intentionally share a shortlisted application using a written summary and an optional explicitly selected résumé. The employer sees the submission snapshot and structured feedback history, not the underlying candidate, application, internal notes, or AI assessment. Feedback never moves stages or sends candidate email. Reviewers remain read-only. Withdrawals bind the expected submission ID so a stale tab cannot withdraw its replacement. Revocation takes effect through live membership and job-grant checks. Already issued private document URLs expire after 60 seconds.

Invitation delivery generates an Auth sign-in link without sending Supabase mail, then sends through the existing Resend adapter and SSR callback. New users set their name/password before accepting. Acceptance verifies the signed-in email and grants only the invited job. Replaying an accepted receipt never restores a removed grant. Resend rotates the token with a compare-and-swap; failure preserves the invitation and delivery history.

Public intake is bounded before parsing. It validates PDF/DOCX signatures, expected screening answers, and required questions. A UUID request key deterministically identifies the application; a hash binds fields and file bytes. Retrying the same request returns its receipt, while changed payloads conflict. A hashed address/job/hour allowance limits abuse; it is not a replacement for a future CAPTCHA or platform-wide rate limiter. Candidate identity remains agency-scoped while submitted name/contact details are application snapshots. Ambiguous upload outcomes retain files rather than deleting a possibly committed document.

Operational lists have deterministic cursors. Notes/activity paginate separately. Received-date filtering uses agency-local calendar days; overview rolling intake windows remain unchanged. A shared public role component keeps preview and publication aligned. Jobs with applications or collaboration history must be closed rather than deleted.

Screening prompt v2 distinguishes related-but-incomplete evidence from absent evidence. The adapter preserves v1 behavior for historical queued runs. Fourteen synthetic model/document cases passed; this is a smoke evaluation, not a production accuracy or real-data privacy approval. Deploy the compatible worker before activating v2 enqueue behavior, or pause scheduling during the coordinated migration/build rollout.

Local verification uses disposable Supabase and synthetic Playwright fixtures with AI/email/enrichment providers disabled. No staging reset, live email, or production data is required. Public agency website intake, advanced identity merging, bulk operations, interviews, offers, and placements remain separate milestones.
